# 客户端与链路排障

管理台的「连接监控」提供版本、桥接、Planet 和链路的处理建议。风险标记可点击查看；未知状态表示观测不足，不能直接当作离线或漏洞。先核对当前节点 ID，再进行变更，避免把旧安装留下的成员误认为当前设备。

## 客户端版本较低

此标记只比较客户端已报告的 ZeroTier 版本和当前 Controller 的 ZeroTier 版本。它**不是漏洞检测，也不代表已经查询上游最新版本**。某些平台更新节奏不同，版本相同也不能证明没有安全问题；按对应项目发布说明评估升级。

1. 记录节点 ID、网络 ID、已分配 IP 与自定义 Planet 的校验和。安全备份客户端身份与配置；身份私钥不得发送给他人、上传仓库或贴入工单。
2. 桌面与服务器使用 [ZeroTier 官方下载](https://www.zerotier.com/download/) 或原可信软件源，检查平台兼容性与发布说明后原地升级。不要删除状态目录、重新生成身份或批量重装。
3. Android 使用自定义 Planet 时，先检查 [ZerotierFix Releases](https://github.com/kaaass/ZerotierFix/releases) 的兼容性、应用签名与 Planet 导入能力。不要因为版本数字较低就换成不能导入自定义 Planet 的客户端。不同来源 APK 未必能覆盖安装；不要直接卸载旧应用。若确实无法保留身份，先安排重新授权和 IP 调整。
4. 重新连接，刷新监控，核对节点 ID 未变、版本更新、成员授权有效且已获 IP，再访问真实目标服务。版本上报可能需要新的客户端连接；只看到绿色状态不能代替业务验证。

Android 的版本号、APK 应用版本与内置 ZeroTier 引擎版本可能不同；监控比较的是后者。

## 桥接权限

桥接标记表示 `activeBridge` 权限开启，**不证明存在环路或流量异常**。

- 不需要二层桥接：进入对应网络的成员列表，关闭该成员的桥接开关。一个设备可能加入多个网络，分别核对权限。
- 确需桥接：保留权限，检查宿主机 bridge 配置、广播流量、路由和环路防护。不要为了消除提示破坏正在使用的二层连接。
- 修改后验证相关设备的实际通信，必要时恢复原设置。

## Planet 不一致或 Root 配置不可用

先区分运行中 Planet 与下载文件的哈希不一致、预期 Root 配置无法读取、发现预期外 PLANET peer 等情况。

1. 备份当前配置，核对两份文件是否来自同一份已签名 World，确认预期的 Root ID 与稳定端点。参考 [多 Root 运维](multi-root.md)。
2. 配置不可用时先恢复配置和诊断数据；文件不一致时通过既有部署流程同步正确文件。不要随意重新签名、移除 Root 或把所有主机改成中转来消除提示。
3. 按实际部署方式重载服务，然后刷新监控。管理台的服务文件一致性检查**不扫描所有客户端的 Planet**；需要客户端重新连接、核对网络配置并验证业务访问。

## 正在请求配置、未知路径或中转

先核对完整网络 ID、手机/电脑当前节点 ID、客户端服务是否运行，以及管理台是否出现该节点：

- **管理台没有节点**：先检查客户端到 Root、Root 到 Controller 的通信；核对自定义 Planet、Root 端点、UDP 规则和宿主机策略。防火墙规则可能仅允许经过已退役 Root 的 Controller 流量。查看管理台的宿主机策略诊断，修复实际受阻规则，勿直接清空整套防火墙。
- **成员已出现但未授权**：确认设备身份后在对应网络授权。已授权但无 IP 时检查地址池、手动 IP 和路由配置。
- **路径未知**：客户端可能尚无最近通信，或者没有可用探针。先从探针访问目标，再刷新；探针到成员的路径不能代表任意两个成员之间的路径。
- **RELAY / TCP RELAY**：表示观测到中转路径，不等于不可用。优化时检查两端 UDP、防火墙、NAT 与 IPv4/IPv6 可达性；双栈下可用的一族可能维持连接。参考 [IPv6 Root](ipv6-roots.md)。

调整后验证真实业务连接。不要关闭唯一 Root 或向公网开放管理台/API 作为链路修复手段。维护窗口内一次调整一项，保留可回退的配置副本。
